# Stable GWCut host bootstrap

The normal operator interface is intentionally invariant across fresh compute hosts, replacements and recoveries.

The operator retains one canonical credential file and always runs the same command sequence:

```bash
chmod 600 /root/gwcut-bootstrap.env
curl -fsSL https://raw.githubusercontent.com/geomlab/gwcut-public/main/stable-bootstrap.sh -o /root/bootstrap.sh
chmod 700 /root/bootstrap.sh
bash /root/bootstrap.sh </root/gwcut-bootstrap.env
```

`stable-bootstrap.sh` is the public release-channel selector. It contains immutable, reviewed 40-character pins for both the public Stage-0 implementation and the private `gwcut-infra` release. The operator therefore does not supply or rotate release SHAs during routine host recovery. Promoting a new production release means changing those two pins through review and CI in this repository; the operator command remains unchanged.

The canonical retained credential file contains:

```text
GITHUB_TOKEN=...
GHCR_READ_TOKEN=...
DASHBOARD_PASSWORD=...
S3_WORKER_ACCESS_KEY=...
S3_WORKER_SECRET_KEY=...
S3_READER_ACCESS_KEY=...
S3_READER_SECRET_KEY=...
S3_BACKUP_ACCESS_KEY=...
S3_BACKUP_SECRET_KEY=...
S3_PITR_ACCESS_KEY=...
S3_PITR_SECRET_KEY=...
S3_BUCKET=...
S3_REGION=...
```

The four S3 access-key IDs are distinct long-lived production identities. Object Storage itself is long-lived production state; recreating the bucket and those identities from nothing is a separate rare provider-provisioning operation, not part of normal compute-host recovery.

The same command and same credential file are used whether the bucket contains no committed GWCut backup or an existing recovery set. The immutable Stage-0 delegates to the private host bootstrap, which decides fail-closed between `fresh-empty`, `restored`, and `existing` states.

Using `main/stable-bootstrap.sh` deliberately makes the `gwcut-public` main branch the release-channel trust root. The selected implementation and private infra remain immutable SHA-pinned behind that stable operator URL. Do not change the pins until the referenced implementations and recovery gates have passed review and CI.
